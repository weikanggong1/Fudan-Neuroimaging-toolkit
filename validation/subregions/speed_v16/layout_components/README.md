# 亚区分割：GPU 批次布局的真实组件验证

[返回组件报告](../components/README.md) · [机器汇总](summary.json) · [归档清单](archive_manifest.json)

本页记录 `v16_c4` 的有效体素布局（compact）和 `v16_c5_driverfix` 的完整网格布局（dense）。输入为同一真实 `sub-01` T1 的保存工作图像、对齐图像、四面体网格及标签表；运行时不调用官方软件。服务器为 gpucw1，共享物理 GPU 0，4 个 CPU 线程，FP32/TF32，CUDA allocator 比例为 0.10。

旧路径逐批传坐标、候选索引和行索引，并在 GPU 上生成小型候选掩膜。新路径先在 CPU 打包同类缓冲区，每类一次传到 GPU，随后创建分批视图；dense 的浮点采样坐标和整数写入坐标分别打包。候选顺序、padding、分组、行重排和实际坐标保持原布局。包围盒索引、有效体素归类及坐标生成仍在 CPU。

两种路径读取同一输入，交替执行，共四轮。第 0 轮单列，随后三轮取中位数；**每轮仍新建 GPU 布局**，这里的预热仅指 CUDA/kernel 等运行状态。CPU 包围盒索引在对照前共建一次，其耗时另列，不计入“布局＋数据项”或“布局＋raster”。这些数值不包含 T1 预处理、Gaussian EM、网格优化迭代和完整分割。

## c4：有效体素布局与数据项梯度

stride=1 使用全部有效体素；stride=4 选固定空间子集。每组旧／新路径使用完全相同的选中体素和 likelihood，比较布局改动；不把两个 stride 的耗时比解释为布局收益。本组件没有比较采样与全量分割精度。

| 真实工作网格 | 有效／选中体素 | 首次布局＋数据项：旧／打包 | 预热新布局：旧／打包 | 预热布局＋数据项：旧／打包 |
|---|---:|---:|---:|---:|
| 丘脑，stride=1 | 717,531 / 717,531 | 4.358 / 0.318 s | 2.584 / 0.186 s | 2.679 / 0.281 s |
| 丘脑，stride=4 | 717,531 / 179,378 | 2.568 / 1.499 s | 2.068 / 0.188 s | 2.106 / 0.221 s |
| 左海马＋杏仁核，stride=1 | 526,626 / 526,626 | 2.248 / 0.247 s | 1.782 / 0.144 s | 1.844 / 0.218 s |
| 左海马＋杏仁核，stride=4 | 526,626 / 131,721 | 2.140 / 0.471 s | 1.684 / 0.142 s | 1.710 / 0.168 s |

“数据项”包含同一 fused 成本及其 backward；不包含形变先验。第 0 轮包含首次 kernel 使用效应，例如丘脑 stride=4 的打包路径成本／梯度为 1.280 秒，随后三轮为 0.033–0.038 秒。首次变化无法单独归因于 JIT，日志没有独立编译计时。

| 数值检查（四轮最大值） | 布局逐张量完全相同 | 数据成本差异 | 梯度相对 L2 差异 | 最大单元素梯度差异 |
|---|---|---:|---:|---:|
| 丘脑，stride=1 | 是 | 0 | 8.56×10⁻⁸ | 2.29×10⁻⁵ |
| 丘脑，stride=4 | 是 | 0 | 7.57×10⁻⁸ | 1.34×10⁻⁵ |
| 左海马＋杏仁核，stride=1 | 是 | 0 | 8.07×10⁻⁸ | 1.53×10⁻⁵ |
| 左海马＋杏仁核，stride=4 | 是 | 0 | 6.56×10⁻⁸ | 3.81×10⁻⁶ |

16 次对照的梯度均有限，全部通过原脚本门槛：布局逐张量相同、成本差为 0、梯度相对 L2 差异小于 2×10⁻⁴。本项没有另行输出稠密 prior／coverage 差异，完整网格检查见下一节。

原始结果：[丘脑 stride=1](v16_c4_layout_thalamus_stride1.json)、[丘脑 stride=4](v16_c4_layout_thalamus_stride4.json)、[左海马 stride=1](v16_c4_layout_hippo-amygdala-left_stride1.json)、[左海马 stride=4](v16_c4_layout_hippo-amygdala-left_stride4.json)。

## c5：完整网格布局与稠密先验

正式结果来自完成并成功保存 JSON 的 `v16_c5_driverfix` 重跑。

| 真实工作网格 | 首次布局＋raster：旧／打包 | 预热新布局：旧／打包 | 预热 raster：旧／打包 | 预热布局＋raster：旧／打包 |
|---|---:|---:|---:|---:|
| 丘脑，148×101×114，14 类 | 13.480 / 0.709 s | 3.479 / 0.254 s | 0.101 / 0.127 s | **3.606 / 0.381 s** |
| 左海马＋杏仁核，156×156×197，13 类 | 8.701 / 0.817 s | 4.558 / 0.470 s | 0.170 / 0.162 s | **4.726 / 0.632 s** |

下降主要出现在布局准备。raster 本身的预热耗时没有一致下降。首次 raster 旧／新分别为丘脑 1.308 / 0.423 秒、左海马 1.237 / 0.351 秒；共享负载与首次使用效应均计入这些测量。

两组共 8 次对照的所有布局张量完全相同，稠密 prior 最大绝对差异为 **0**，coverage 分歧为 **0 个体素**，均通过正式脚本数值门槛。原始结果：[丘脑](v16_c5_driverfix_dense_layout_thalamus.json)、[左海马＋杏仁核](v16_c5_driverfix_dense_layout_hippo-amygdala-left.json)。

## 单列的失败运行：报告序列化

最初 `v16_c5` 丘脑测量打印了四轮数值，随后保存 JSON 时因 shape 中的 NumPy `int32` 触发 `TypeError: Object of type int32 is not JSON serializable`，exit code 为 1；左海马测量未启动。该次 stdout 中旧路径后三轮“布局＋raster”中位数约 15.8 秒，但没有成功保存的正式结果 JSON，未纳入上面的结果或观察比值。

驱动修复将 shape 元素转换为 Python `int`，产品 `rasterize.py` 的 SHA-256 与 c5 冻结版本相同。重跑时共享 GPU 负载已变化，使用新生成的正式 JSON，未混用失败日志的计时。失败证据：[日志](v16_c5_dense_layout_thalamus.log)、[状态](v16_c5_components_status.json)。

## 来源与核验

每个正式 JSON 保存四项输入的路径、大小和 SHA-256，以及 benchmark 驱动和 `rasterize.py` 的 SHA-256。c4 两个源码文件与 [c4 冻结清单](../v16_c4/source_manifest.json)相符；正式 dense 重跑的产品源码与 [c5 冻结清单](../v16_c5/source_manifest.json)相符，驱动修复后的独立 SHA 写于正式结果。

30 个结果、日志和状态文件以及[另行归档的三个实际运行驱动](driver_archive_manifest.json)均已逐项核对大小和 SHA-256。三个驱动均明确设置 `CUDA_VISIBLE_DEVICES=0`；驱动文件在运行结束后检查归档，启动与子进程 PID 另由 launch、status 和 GPU 监测记录支持。

[c5 原冻结源码服务器核验](v16_c5_source_remote_verification.json)与[驱动修复源码服务器核验](v16_c5_driverfix_source_remote_verification.json)均无不匹配项。归档文件的字节数与 SHA-256 核对结果、六组数值门槛和全部原始计时位于 [summary.json](summary.json)。这是布局组件验证；整例分割耗时及解剖精度另行记录。
