# 10 例公开 T1：当前实现与官方实现的比较设计

## 固定数据与源码

使用 OpenNeuro `ds000114` snapshot `1.0.2` 全部十名受试者的 `ses-test` T1。每人一张，按编号预先固定，没有根据 Dice 更换病例。公开数据已去脸，本轮不追加去脸或替换为项目 example。文件、体素数组、几何及版本已分别校验，见 [数据来源](data_selection.md)。

报告全部 10 例，并另列未参与此前单例开发的 9 例。`sub-01` 标记 `development_seen=True`，本次重新运行，不复用其旧官方输出。此前缓存衍生 T1 与本次公开 snapshot 的体素不同。

当前生产源码固定为 `ac692bb4f7868a24ea4bd67180162e81726de9b4`。不可变清单 [expected_source_manifest.json](expected_source_manifest.json) SHA-256 为 `d8c8f7aecdae521751f30fdd09bea6acbffd2c0a50c9fb70e1dc97ad74717b07`，核实 432 个文件、428 个原生 Python 模块。分割的 GEMS 文件与此前通过重复性验证的版本逐文件相同。运行中的拟合参数、算法及生产源码均固定；官方环境准备问题仅修复 benchmark 脚本。

## 两种输入模式与四种评价空间

| 模式 | FNIT 输入 | 原网格评价 | 高分辨率评价 |
|---|---|---|---|
| `raw` | 同一份公开 T1；包含共享 SynthSeg+、TorchFAST、白质代理与全部细分区 | 该例公开 T1 的真实 shape/affine | 官方高分辨率轴、间距和整数相位，联合双方 FOV |
| `stage` | 该例本轮官方 `recon-all` 生成的 `norm/aseg/wmparc` | 该例 `norm.mgz` 网格 | 同一官方高分辨率轴、间距和整数相位，联合双方 FOV |

两种模式均调用公开函数 `segment_4_subregions(structures="all", optimization="fast", threads=4)`，保存原网格和四项高分辨率标签。官方细分区标签不进入 FNIT 拟合。`stage` 在本例新 `recon-all` 成功后运行，可以与官方细分区并行。

官方每例从同一公开 T1 执行新的 `recon-all -all -openmp 4`，再依次执行脑干、丘脑及双侧海马/杏仁核分割，见[完整官方命令及环境](official_protocol.md)。官方运行在 CPU，FNIT 运行在 H100；CPU/GPU 算法、完整流程和相同阶段的对比分别列明。

原网格使用最近邻映射官方标签到该模式实际输入网格。高分辨率只扩展 FOV；不为评分拟合配准、偏移或相位。右侧海马/杏仁核官方 ID 在比较时加 10000，与 FNIT 统一 ID 对应。

## 指标与汇总

每例固定 110 个 ROI、四个评价空间，共 440 行；十例保留 4400 行。报告 Dice、Jaccard、双方硬体积和软体积，以及绝对和相对体积差。双方硬标签均空时 Dice/Jaccard 为 NA；只有一方存在时为 0，不能删去小核或零 Dice。

家族分为脑干、丘脑、左/右海马、左/右杏仁核。家族 Dice 按本例官方 ROI 体素数加权，另列细标签算术平均与家族前景 Dice。十例汇总使用每名受试者的指标分布，包括均值、样本标准差、范围和有效例数；不将不同受试者之间的差异称为算法随机波动。此前[同一输入三次重复验证](../reproducibility_20261002/README.md)单独保留。

失败病例仍保留在十例计划分母和 4400 行表内，指标为 NA 并注明原因。记录数据准备、环境准备、依赖中止、进程失败及结果核验失败；成功重跑使用相同输入和生产源码，保留各次尝试。

## 计时与资源

FNIT 分别报告 API 计算、保存、API 总时间和独立进程墙钟；观察器额外计时单列，保留其实际开销。输入校验、等待官方预处理、GPU 空闲显存等待均单列，不加入拟合进程耗时。

官方报告本轮原始 T1 完整流程墙钟、`recon-all`、三个细分区命令及官方显式阶段 timer。没有独立计量或共同中间标签的步骤不填估算耗时或步骤 Dice；不复用历史个体的重建时间。

服务器 `gpucw1` 有两块 H100、双路 Intel Xeon Gold 6430（128 个逻辑 CPU、64 个物理核）和约 1 TiB 内存，见 [硬件身份](hardware_identity.json)。官方四例并发、每例四线程；FNIT raw 与 stage 分别固定 GPU 1 和 GPU 0，每块 GPU 的自身队列依次运行。允许共享 GPU，记录物理 UUID、其他进程、利用率和自身 PID 显存。自身采样显存上限 19073 MiB（20 GB），CUDA 使用现有 FP32/TF32 与确定性累计，不使用 FP16。实际共享负载随日志公开。

## 数值与来源核验

每例核验输入、冻结源码、真实导入路径、图谱/权重、官方输出和监视日志的大小及 SHA-256。检查全部已保存标签体素有限、整数且属于指定支持；全部硬/软体积有限非负，硬体积与保存标签计数一致；四项拟合网格的已保存最小 Jacobian 有限且为正。此项核验范围为拟合四面体网格的最小值，没有保存或声称逐体素 Jacobian 图检查。

图谱、权重和许可证不进入 Git；本轮只发布数值结果、脚本、来源清单及局部脑图。资产校验与原资源来源单独记录。
