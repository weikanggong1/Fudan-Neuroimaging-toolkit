# 任务 3 实测与接入结论

本轮起点为 `f07cf59c7f51ae1393e2578f141b4d130ed7801a`，主机 gpucw1，目标 GPU `GPU-e25cac06-0ce8-a833-abf9-09ab18c9c9ba`，OMP/MKL/OpenBLAS/Numba 各配置 4 线程，FP16/BF16 未启用。每份 JSON 保留当次源码、输入、资源和程序哈希；后续提交不会将旧报告重标为新实测。两例来自冻结的 FNIT 自产检查点，官方产物没有进入计算。

## 已完成的同输入阶段

WM 后编辑 GPU callable 可供调度接入。两例、两个步骤的 ABBA（CPU/GPU/GPU/CPU）都保持体素完全一致，几何和 dtype 相同，逐值 Dice 全为 1。这里比较的是成熟 FNIT CPU 后编辑；原生完整编辑核心没有被替换。秒数包含函数读写、搬运和保存，不含解释器导入。

| 输入 | 步骤 | CPU A | GPU B（首次） | GPU B（重复） | CPU A（重复） | 不同体素 |
|---|---|---:|---:|---:|---:|---:|
| sub01 | ento | 1.823 | 2.665 | 0.966 | 1.744 | 0 |
| sub01 | ACJ | 2.830 | 1.153 | 1.103 | 2.726 | 0 |
| sub02 | ento | 1.925 | 1.000 | 1.001 | 1.801 | 0 |
| sub02 | ACJ | 2.855 | 1.134 | 1.168 | 3.003 | 0 |

sub01 ento 首次 CUDA 冷启动较慢，不能只列重复结果。真实体积之外补测了双侧重叠和边缘种子的针对性单元输入，验证原 c/r/s 扫描的最后邻居规则。数据见 `wm_v2.json`。Torch reserved 最大观测 538,968,064 字节（0.539 GB／0.502 GiB），文件入口结束 allocated=0；这不是全进程峰值。阶段脚本只有进程显存快照，连续链脚本补充同期进程树监测。

GPU GCA 搜索评分仍属实验接口，不是完整 EM 后端。`gca_v4.json` 对两例的全部 8 轮平移搜索，最终矩阵和每轮分数均完全相同；17.274→3.767 秒、16.853→3.756 秒。计时不包含图谱预备、首次 JIT、上传和完整后续 EM，不能代表完整 GCA 阶段。随机抽取 256 个稳定样本候选时，各例仍有 1 个分数差 4.768e-7；16 个全样本候选没有差异。预先声明的评分门槛是 0，v4 因而不能标为全部严格通过。

这个尾差来自成熟 Numba 评分的 FP32 `sqrt/log` 重载，Python FP64 对数不相同。当前修正使用同一 Numba 对数项缓存，新增专项测试通过；真实评分与完整平移的 v5 正在共享锁队列中，结果以独立报告补入。旧 v1/v4 差异记录保留，评分门槛不改变。GPU 评分代码不修改成熟 CPU 分数定义。

## 完整 GCA 的候选与现有原生程序

完整优化器保留稳定样本 EM、全样本 EM、梯度、接受/拒绝及终止循环。有限缓存补丁仅改变普通单输入 uint8 搜索似然热点，源码固定到 FreeSurfer `d932c45b7941662ea380a05efef580568b98d41a`，在原 Conda 工具链独立构建。两例完整阶段配对的 LTA 数值矩阵完全一致，但候选显著变慢，**拒绝默认启用，也不替换旧二进制**。

| 输入 | 现有程序（秒） | 缓存候选 v1（秒） | 不同矩阵元素 | 最大误差 | 决策 |
|---|---:|---:|---:|---:|---|
| sub01 | 222.820 | 391.213 | 0 | 0 | 保留现有程序 |
| sub02 | 186.475 | 327.739 | 0 | 0 | 保留现有程序 |

配对顺序为 sub01 原程序→候选，sub02 候选→原程序。同一局部 `/tmp` 锁保护，两例均正常执行完整调用。LTA 文件 SHA 不同，因为程序及命令行来源文字不同；矩阵逐元素比较独立于文件 SHA。阶段输出的完整网格信息回归由连续链补充。数据见 `native_pair_v1.json`，构建见 `native_build_v1.json`。

候选实际编译最后生效的优化旗标是 `-O3 -DNDEBUG`，保留 OpenMP，链接原固定构建对象和库。v2 只增加能力查询，评分头主体与 v1 相同；v2 构建报告补充原始对象/静态库及 gca.cpp/gca.h 哈希。v1 两例不能重标为 v2 实测。新二进制 `original`／`cpu_cached` 单例配对已排队，记录原生 PID、实际线程和 RSS；尚不将变慢归因于 OpenMP、算法或动态库。各后端完整似然调用次数没有仪表计数，不能从日志推断为准确调用数。

原程序完整阶段 profile 含 perf 开销，共 226.047 秒。按刷新 stdout 的边界：平移 16.915 秒、线性搜索 153.248 秒、稳定 EM 与全样本准备合计 4.148 秒、最终 EM 47.504 秒。CPU self 采样：似然入口 16.25%、MatrixMultiply 15.62%、log 14.19%、体积采样 12.98%、OpenMP 等待 11.39%。这些是 CPU 样本比例，不能当作墙钟比例；旧 perf 有 DWARF 警告，未得到可信的梯度／线搜索独立墙钟。详见 `native_hotspots.json`、`native_perf_report.txt`。

## N4、连续链和整例边界

N4 仅审查已有真实 profile 与当前实际程序 SHA，没有新增候选 benchmark。先前整例绑定 `ff372d73f106e850b999fbc95ae0b324cd315cbf`：拟合 120.292／120.794 秒，B-spline 重建约 1.005 秒、指数与拷贝 0.402／0.418 秒，拟合约占 98.6%。继续保留 ITK N4 和现有 1 线程默认，不为约 1.4 秒重建扩大线程，不启用平滑残差替代算法。见 `n4_audit.json`。

本任务连续链从自产 nu/brainmask/SynthSeg/affine 的冻结边界开始。GCA 及以下全部输出重新计算，没有复制 norm、aseg、WM 或 filled。完整 GCA 使用现有默认，WM 两项后编辑使用 GPU callable。两例运行已排队，每例分别取得并释放锁。完整链秒数包含导入、资源校验、拷贝、计算、比较和输出，分步骤有嵌套范围，不能把它们和整体重复相加。该链不计为原始 T1 空目录整例。

138 项严格诊断、全模型 GPU 调用和两例原始 T1 空目录整例由协调者统一验收。阶段收益不相加为整例收益。整体指标等效始终 `not_assessed`。当前本目录不发布真实影像或脑图；逐体素差异、逐标签 Dice 及实际图像留在授权服务器，协调者可在授权检查环境查看。

## 资源与测量限制

GCA 71,651,552 字节，SHA-256 `2fcd276a39800f01f93a4c8828ae6d0a8cea3d8b8b9fe1599d4ee54e806be93e`，按固定资源清单核验；EntoWM 和 LUT 在连续链按现有清单校验大小和 SHA。没有新增下载或重新发布资源。许可证只通过已授权环境继承。

早期 GPFS 锁返回 ENOLCK；gca_v3/wm_v1 没有执行，不能计为结果。后续 v4/v2/native 配对使用主机本地锁。锁只隔离本轮任务，目标 GPU 上仍存在外部进程；日志保留采样。v4 请求 0.5 秒采样，实际最大间隔 3.239 秒，无失败；进程 31685 的观测最大值为 843,055,104 字节，其他 PID 不算本任务显存。它不是未采样瞬间的峰值，也没有完整 PID 树，不能凭此宣布整例显存已验收。预算为 20,000,000,000 字节（20 GB／18.626 GiB）。

## 最近版本与复现

- v1 GPU：评分尾差，真实平移矩阵相同；保留诊断报告。
- v3 GPU／WM v1：GPFS ENOLCK，没有执行。
- v4 GPU：双精度半入舍入和 FP32 除法兼容，真实平移完全相同，稳定评分仍有 1/256 尾差。
- 当前 GPU v5：Numba FP32 对数项缓存，4 项专项测试通过，真实回归排队。
- WM v2：两例 uint8 ABBA 和边缘／重叠测试全部通过。当前文件入口另修正 MGH 多字节上传的字节序兼容，uint8 数值不变；连续链使用当前版本回归。
- 原生缓存 v1：两例完整 LTA 矩阵相同，但约 1.76 倍慢，拒绝默认启用。
- 原生缓存 v2：只补能力查询和构建输入哈希，单例同构建控制排队。
