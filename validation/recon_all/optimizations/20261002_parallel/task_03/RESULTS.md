sub01 ento 首次 CUDA 冷启动较慢，不能只列重复结果。真实体积之外补测了双侧重叠和边缘种子的针对性单元输入，验证原 c/r/s 扫描的最后邻居规则。数据见 `wm_v2.json`。Torch reserved 最大观测 538,968,064 字节（0.539 GB／0.502 GiB），文件入口结束 allocated=0；这不是全进程峰值。阶段脚本只有进程显存快照，连续链脚本补充同期进程树监测。

GPU GCA 搜索评分仍属实验接口，不是完整 EM 后端。`gca_v4.json` 对两例的全部 8 轮平移搜索，最终矩阵和每轮分数均完全相同；17.274→3.767 秒、16.853→3.756 秒。计时不包含图谱预备、首次 JIT、上传和完整后续 EM，不能代表完整 GCA 阶段。随机抽取 256 个稳定样本候选时，各例仍有 1 个分数差 4.768e-7；16 个全样本候选没有差异。预先声明的评分门槛是 0，v4 因而不能标为全部严格通过。当前 v5 严格门槛仍为 0；两例稳定 256 个和全样本 16 个候选均零差异，默认 float64 上下文下的真实稳定候选仍零差异，指定边界舍入测试通过。当前平移为 17.027→3.371 秒、17.326→3.328 秒，矩阵与 8 轮分数都完全一致；仍不是完整 EM 提速。v5 实际源码快照绑定 `60f08b4c4bdbdeca11b536990b2c66e9a88390bc`，保留旧 dispatch 标签而没有改标历史报告。

这个尾差来自成熟 Numba 评分的 FP32 `sqrt/log` 重载，Python FP64 对数不相同。当前修正使用同一 Numba 对数项缓存，新增专项测试通过，并将坐标缓冲固定为 FP32，避免调用者默认 float64 改变边界舍入；真实评分、默认 dtype 边界测试与完整平移的 v5 已完成并通过，见 `gca_v5.json` 与 `gca_v5_scores.csv`。旧 v1/v4 差异记录保留，评分门槛不改变。GPU 评分代码不修改成熟 CPU 分数定义。

## 完整 GCA 的候选与现有原生程序

完整优化器保留稳定样本 EM、全样本 EM、梯度、接受/拒绝及终止循环。有限缓存补丁仅改变普通单输入 uint8 搜索似然热点，源码固定到 FreeSurfer `d932c45b7941662ea380a05efef580568b98d41a`，在原 Conda 工具链独立构建。历史 v1 两例完整阶段配对的 LTA 数值矩阵完全一致，但候选显著变慢，拒绝该版默认启用；当前 v3 的两例改善和连续链见后文。

|---|---:|---:|---:|---:|---|
| sub01 | 222.820 | 391.213 | 0 | 0 | 保留现有程序 |
| sub02 | 186.475 | 327.739 | 0 | 0 | 保留现有程序 |

配对顺序为 sub01 原程序→候选，sub02 候选→原程序。同一局部 `/tmp` 锁保护，两例均正常执行完整调用。LTA 文件 SHA 不同，因为程序及命令行来源文字不同；矩阵逐元素比较独立于文件 SHA。阶段输出的完整网格信息回归由连续链补充。数据见 `native_pair_v1.json`，构建见 `native_build_v1.json`。

候选实际编译最后生效的优化旗标是 `-O3 -DNDEBUG`，保留 OpenMP，链接原固定构建对象和库。v2 只增加能力查询，评分头主体与 v1 相同；v2 构建报告补充原始对象/静态库及 gca.cpp/gca.h 哈希。v1 两例不能重标为 v2 实测。新二进制 `original`／`cpu_cached` 单例配对已完成：同一 SHA-256 程序原始后端 221.191 秒、缓存后端 389.330 秒，LTA 矩阵仍零差异。两次实际线程峰值均为 4，映射的 libomp 与 ITK VNL 路径相同，正常后端与旧程序的 222.820 秒接近。构建／运行库差异不足以解释这个控制中的变慢；缓存实现／接入路径存在性能退化。随后核查发现，上游 gca.cpp 第 2 行启用了可复现 ROMP 分块规约，v1/v2 缓存却使用普通 `fast` 级规约；默认 ROMP 等级可使缓存评分循环串行。全进程 Threads 峰值 4 不能证明该评分循环用了 4 个线程。因此 v1/v2 还存在规约／调度模式偏离，不能仅凭最终矩阵相同标为算法边界完全保持。当前 v3 改为调用上游 ROMP 分块规约宏，恢复其样本区间、块内顺序、块间规约和线程级别；两例重新配对均已完成，详见末尾当前验收。首例 v3 完成：原始 219.740 秒、缓存 187.703 秒，矩阵零差异；两后端评分入口均 1,704,272 次，缓存只刷新 2,841 个密度项，实际 fast=0／reproducible=1。第二例与两例完整候选连续链后来均完成，见末尾当前验收；本任务不修改生产默认。见 `native_same_build_v2_sub01.json`／CSV。v1/v2 没有精确调用计数。v3 增加显式 `FNIT_GCA_DIAGNOSTICS=1`，记录有限补丁入口的普通原始／缓存评分调用次数、样本数、密度刷新数和实际 ROMP 许可级别；不声称覆盖程序所有梯度／概率调用。

原程序完整阶段 profile 含 perf 开销，共 226.047 秒。按刷新 stdout 的边界：平移 16.915 秒、线性搜索 153.248 秒、稳定 EM 与全样本准备合计 4.148 秒、最终 EM 47.504 秒。CPU self 采样：似然入口 16.25%、MatrixMultiply 15.62%、log 14.19%、体积采样 12.98%、OpenMP 等待 11.39%。这些是 CPU 样本比例，不能当作墙钟比例；旧 perf 有 DWARF 警告，未得到可信的梯度／线搜索独立墙钟。详见 `native_hotspots.json`、`native_perf_report.txt`。
