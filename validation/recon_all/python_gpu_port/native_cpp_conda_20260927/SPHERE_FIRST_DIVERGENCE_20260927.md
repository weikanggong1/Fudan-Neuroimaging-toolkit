# FreeSurfer Conda sphere same-input first-divergence diagnostic

Date: 2026-09-27. Scope: one frozen LH subject on gpucw1; all new build and runtime files were written to `/tmp`. This is the Conda-built native C++ compatibility question, separate from the uncommitted Python `mris_register` port. No production source, clean integration worktree, or GitHub branch was modified.

## Provenance and acceptance boundary

The 111-file frozen input manifest SHA-256 is `6b209e92dd1565543082418d5c08450ae6cd3c9cf773879f1b2ce52c9b01df2f` in every paired trial. Official installed FreeSurfer 8.2 `mris_sphere` binary SHA-256 is `c34ca308a7fa03acdb3f689bf6125cf3d0198c37c3a62992a29f68e631c73612`; original Conda binary `ba319a1fe45b4a5aea7c3438d9c2fe0bb062b6f731caf71709baf998b9b78a99`. Both derive from pinned source commit `d932c45b7941662ea380a05efef580568b98d41a`; official build is GCC 4.8.5, Conda build GCC 11.4.0.

The first observed source difference is `mris_sphere.cpp:299-300`: unqualified `abs(float span)` truncates to int in the official GCC 4.8 binary and remains floating point in Conda GCC 11. An isolated explicit `abs((int)span)` binary SHA-256 `1ad65ead33ef271a2ba7f44ab6e31ade2d4b806e9e925bead042c6afc9c06b21` corrected this first behavior. Full output, already paired in `SPHERE_ABS_INT_TRIAL.md`, worsened from Conda mean vertex distance 2.434603 mm to 5.715858 mm against official, so the patch is **not accepted**.

## New bounded paired checkpoints

Set `FS_LICENSE` to the existing private license path, `FREESURFER_HOME` to the same 15-asset directory, `OMP_NUM_THREADS=4`, and run `mris_sphere -threads 4 -seed 1234` on the exact frozen `lh.inflated` with `lh.smoothwm`. `DIAG=0x8 DIAG_VERBOSE=1` wrote `before` (after scaling) and `after` (after projection), and the processes were terminated before `MRISunfold`. The trial `abs((int)span)` matched official ordered coordinates 117777/117777 and faces 235550/235550 exactly at **both** checkpoints. Original Conda differed at 353331 coordinate scalars before projection, with mean vertex distance 0.0935335 mm; after projection it differed at 103277 scalars, maximum vertex distance 1.1444e-5 mm. Full evidence: gpucw1 `/tmp/fnit_sphere_preunfold_probe_20260927/preunfold_full_input_comparison.json`.

Next, two independent full 111-file input copies under gpucw1 `/tmp/fnit_sphere_firststep_probe_20260927/{official,abs_int}` were verified against the same manifest. `mris_sphere -threads 4 -seed 1234 -W 1` wrote the first `MRISintegrate` snapshots `lh.sphere0000` and `lh.sphere0001`; each process was terminated immediately after the latter file appeared. At 0000, trial and official had 117777/117777 exact ordered vertices and 235550/235550 exact faces. At 0001, faces remained exact but 91799 coordinate scalars differed; 69057/117777 vertices were exact; mean vertex distance was 3.67601e-6 mm and maximum 6.00739e-5 mm. Observed runtime to 0001 was 27.568 s official and 26.088 s trial under shared node load. Full evidence: gpucw1 `/tmp/fnit_sphere_firststep_probe_20260927/firststep_full_input_comparison.json`.

A paired one-thread repeat yielded **identical** 0000 and 0001 comparison statistics (official 31.678 s, trial 28.634 s), so this earliest mismatch does not depend on 4-thread OpenMP scheduling. The two first-step displacement vectors correlate 0.99999999999918; the trial displacement has least-squares global scale 0.999995809 relative to official, with residual RMS 1.451e-6 mm versus step RMS 1.135 mm. This strongly suggests the first line minimizer step size is slightly different; it does not prove the precise SSE, gradient, matrix-inverse, or projection sub-operator. Evidence: gpucw1 `/tmp/fnit_sphere_firststep_probe_20260927/firststep_thread_comparison.json` and `firststep_displacement_diagnostic.json`.

## Isolated compiler-flag falsification

Only `utils/mrisurf_integrate.cpp` was recompiled with `-fno-tree-vectorize` added after the existing `-O3` and `-ftree-vectorize`; source SHA-256 `6e3a7bce0372437f1d61acc28c06e813bdb371e17377a4c180f782fddff3f667`. Its object replaced the one member in an isolated copy of `libutils.a`, linked with the previously patched `abs((int)span)` `mris_sphere.cpp` object. All modified objects, library, binary and build script are in gpucw1 `/tmp/fnit_sphere_fp_compat_20260927/no_vector`. New binary SHA-256 `1331934b23c90b01a8d242bfc28846b0082452fbda207e0ad67a9975c9de11ec`; build script SHA-256 `39736545eae07acade643b9474d2decc94b3240231f794898c9a353a71007d86`. The full frozen input manifest matched. 0000 stayed exact; 0001 had **the same** 91799 scalar differences, 3.67601e-6 mm mean and 6.00739e-5 mm maximum. Runtime to 0001 was 26.091 s. SIMD vectorization is therefore not the first-step cause. Evidence: `build_result.json` and `firststep_accuracy.json` in that directory.

## Decision and cleanup

No numerical compatibility fix passed complete ordered-vertex output, so neither the explicit-int `abs` nor `-fno-tree-vectorize` trial should be merged or described as a working replacement. The earliest proven unresolved boundary is the first `MRISintegrate` update inside `mrisRemoveNegativeArea`; the likely next code to instrument is `mrisLineMinimize` at `utils/mrisurf_integrate.cpp:1689` and its force/SSE input, using precise intermediate values. Official binary is stripped, which prevented direct symbol-based comparison here. The independent `mris_register` same-input difference from `SPHERE_REGISTRATION_SAME_INPUT.md` remains uncorrected: 353319/353331 coordinate scalars differed in final sphere.reg, mean vertex distance 0.1616 mm.

A verbose `-W 1` attempt triggered an installed-program diagnostic crash at `MRISwriteAreaError`; it was not used for comparisons. The prior diagnostic had incidentally written two files in the frozen source surf directory: `lh.sphere0000` and `lh.sphere0000.area_error`. Both were removed. Recomputing the frozen source subject manifest excluding its pre-existing output `lh.sphere` matched the archived manifest byte-for-byte, SHA-256 `6b209e92dd1565543082418d5c08450ae6cd3c9cf773879f1b2ce52c9b01df2f`. Evidence: gpucw1 `/tmp/fnit_sphere_preunfold_probe_20260927/frozen_source_restored_manifest.sha256`.

If a future replacement passes the full paired sphere and register tests, the public Conda C++ stage documentation and the existing mismatch reports must be updated to point to that verified implementation; this trial creates no superseding code or documentation.
