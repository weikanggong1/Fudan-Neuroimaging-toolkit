# Connected T1 intensity normalization

The input was `nu.mgz` generated by the one-call Python T1-to-N4 chain on
control-host from the original `sub-01_T1w.nii.gz`. Python
`fnit.recon_all.normalization.pipeline.normalize_t1` used the same chain's
Talairach transform and wrote `T1.mgz` on CPU. A separate, installed
FreeSurfer 8.2 `mri_normalize -g 1 -seed 1234 -mprage` call used that **same
Python-generated `nu.mgz`** as input. The native executable was used only to
make the reference.

| Reference | Differing voxels / 16,777,216 | Maximum intensity difference | MGH header and payload |
| --- | ---: | ---: | --- |
| Fresh official `mri_normalize`, same `nu.mgz` input | 0 | 0 | identical |
| Archived unmodified full FreeSurfer reconstruction | 112 | 2 | different |
| Archived hybrid full reconstruction | 112 | 2 | different |

The archived N4 output already differs from the fresh same-host official and
Python `nu.mgz` at 34 voxels. The exact same-input normalization comparison
shows that the current Python port does not add a voxel mismatch at this
stage. It does **not** prove that all 112 archived differences come only from
N4; that causal attribution requires replaying the archived `nu.mgz` through
the same native and Python commands and comparing their outputs. The current
connected chain therefore remains below the strict archived-subject volume
gate.

The [same-input report](connected_t1_normalize_same_input_native_20260926.json)
records output SHA-256 values, all-voxel comparison, dtype, affine and MGH
header/payload checks. The [archive report](connected_t1_normalize_comparison_20260926.json)
records both historical comparisons. Python normalization took 59.01 seconds
in this one CPU run; the native log reported 1 minute 15 seconds for 3-D bias
adjustment, which does not cover the same timing boundary. No paired speed
ratio is claimed. The chain currently stops at `T1.mgz`.
