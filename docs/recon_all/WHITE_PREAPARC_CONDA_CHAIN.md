# Conda white.preaparc from an exact FNIT prefix

`fnit.recon_all.white_preaparc_conda.run_white_preaparc(subject_dir, hemi, binary, assets_dir, threads=4)`
connects the existing Python gray/white threshold calculation to the
source-built Conda `mris_place_surface` binary. It requires these files:

| Input | Meaning |
| --- | --- |
| `mri/brain.finalsurfs.mgz` | Post-mask and post-edit intensity volume |
| `mri/wm.mgz` | White-matter segmentation |
| `mri/aseg.presurf.mgz` | Pre-surface anatomical segmentation |
| `surf/H.orig.premesh` | Threshold sampling surface |
| `surf/H.orig` | Topology-repaired placement input |
| `binary` | Conda-built FreeSurfer 8.2 `mris_place_surface` |
| `assets_dir` | External FreeSurfer data directory |

`H` is `lh` or `rh`. It writes
`surf/autodet.gw.stats.H.dat`, `surf/H.white.preaparc` and
`mri/mrisps.wpa.mgz`. The last diagnostic path is shared by the two
hemispheres and is overwritten on the second call, as in recon-all.
The return dictionary gives all output paths plus threshold and placement
seconds. This wrapper does not run FreeSurfer Python scripts or depend on a
FreeSurfer installation; the native executable must be built and installed
inside Conda. The tested binary SHA-256 was
`9a42f5d7b70a066daf12e67fb6a0924048b4778186ea772e8976722b226b35d5`,
compiled from FreeSurfer source commit
`d932c45b7941662ea380a05efef580568b98d41a`. Set `FS_LICENSE`
in the environment if the binary requires a license. Placement uses CPU
C++; thresholds use Python/Numba.

Python API:

```python
from fnit.recon_all.white_preaparc_conda import run_white_preaparc

result = run_white_preaparc(
    "/path/to/subjects/sub01", "lh",
    "/path/to/conda-native/bin/mris_place_surface",
    "/path/to/fnit-assets", threads=4,
)
```

Command line:

```bash
python -m fnit.recon_all.white_preaparc_conda \
  /path/to/subjects/sub01 lh \
  --binary /path/to/conda-native/bin/mris_place_surface \
  --assets-dir /path/to/fnit-assets --threads 4
```

The equivalent FreeSurfer 8.2 commands, from the subject's `mri`
directory, are:

```bash
mris_autodet_gwstats --o ../surf/autodet.gw.stats.lh.dat \
  --i brain.finalsurfs.mgz --wm wm.mgz --surf ../surf/lh.orig.premesh
mris_place_surface --adgws-in ../surf/autodet.gw.stats.lh.dat \
  --wm wm.mgz --threads 4 --invol brain.finalsurfs.mgz --lh \
  --i ../surf/lh.orig --o ../surf/lh.white.preaparc --white \
  --seg aseg.presurf.mgz --restore-255 --nsmooth 5 \
  --rip-bg-no-annot --rip-bg --rip-bg-lof --restore-255 \
  --outvol mrisps.wpa.mgz
```

Replace `lh` with `rh` for the right hemisphere.

## Real T1 candidate-prefix validation

The real scan is `examples/data/sub-01_T1w.nii.gz`, SHA-256
`f20410a4efd8e6a05cd04d55730a4a5492ecf9ad1b234fe0fd4661e448270c6a`.
The candidate `orig` and `orig.premesh` meshes were produced by the FNIT
Python sphere, patched Conda topology GA, and Python remesh chain. That
saved topology scratch subject still symlinked **official `brain`, `wm`,
`filled`, and `norm` MRI files**; `brain` and `wm` are topology GA inputs.
The corresponding v5 candidate MRI files were separately voxel-exact, but
this placement trial does not prove that their metadata has no effect on GA.
Both meshes have exactly the same ordered coordinates and faces as the FreeSurfer 8.2
reference for this T1. FNIT v5 generated `wm` and `aseg.presurf` have
zero mismatched voxels against the reference. The candidate
`brain.finalsurfs` was generated by FNIT's five-step Python chain using
FNIT `brain`, `brainmask`, `entowm`, `aseg.presurf`, and **borrowed
official `mca-dura` and `vsinus` labels**. Its 16,777,216 voxel values
match the official finalsurfs exactly. These two labels are the borrowed upstream boundary **of this placement
test**; it is not an independent T1-to-surface run. A separate test has
since generated candidate auxiliary labels, but they were not the inputs
to these placement calls.

On these candidate-derived inputs, both Python threshold files were
byte-identical to the official files. Both Conda C++ placement calls
preserved the ordered faces. Same-index vertex errors below are **3D
Euclidean displacements** from the saved official `H.white.preaparc`.
The baseline is the earlier exact-orig probe, which copied a smoothed
`orig` into `H.white.preaparc`. Thus the baseline and placed outputs
have the same vertex correspondence and output name.

| Hemisphere | Ordered vertices / faces | Approximate mean / P99, mm | Placed mean / P99, mm | Placed max, mm | Vertices >0.1 mm, approximate → placed |
| --- | ---: | ---: | ---: | ---: | ---: |
| LH | 106,622 / 213,240 | 0.802314 / 3.141148 | **0.000420574 / 0.006998961** | 0.630004 | 101,587 → **50** |
| RH | 105,541 / 211,078 | 0.795679 / 3.147371 | **0.000387517 / 0.005624803** | 0.638907 | 100,299 → **50** |

The diagnostic `mrisps.wpa.mgz` had zero voxel differences in each
hemisphere; the candidate file hashes differ in nonvoxel bytes. Observed
wall times with four CPU threads were:

| Stage | FNIT LH / RH, s | Archived official LH / RH, s |
| --- | ---: | ---: |
| Gray/white thresholds | 6.15 / 5.14 | 3.98 / 4.29 |
| White pre-aparc placement | 251.11 / 233.60 | 242.65 / 250.39 |

These were one run per side under different shared-node load; another CPU
model task overlapped the candidate RH run. The archived fully official
frozen-input Conda LH replay gave the same mean/P99/max numerical errors
as this candidate-prefix LH replay, but took 149.46 s on a different day.
These numbers do not support an equivalent-speed claim.

Raw [LH](../../validation/recon_all/python_gpu_port/white_candidate_chain_20260927/lh.json)
and [RH](../../validation/recon_all/python_gpu_port/white_candidate_chain_20260927/rh.json)
placement comparisons include ordered-coordinate equality counts, input
hashes, thresholds, diagnostic voxels and elapsed times. The same-stage
[baseline LH](../../validation/recon_all/python_gpu_port/white_candidate_chain_20260927/lh_stage_baseline.json)
and [baseline RH](../../validation/recon_all/python_gpu_port/white_candidate_chain_20260927/rh_stage_baseline.json)
records give full prior-error distributions.

The older final `white` surface had about 0.44 mm mean
absolute **coordinate-component** error against official final `white`;
that later-stage/different-statistic result is not a direct ratio to
pre-aparc Euclidean displacement. The 50 pre-aparc outliers per hemisphere arise after
identical initial smoothing in the Conda versus official floating-point
placement optimizer. The [source-level diagnosis](../../validation/recon_all/python_gpu_port/native_cpp_conda_20260927/WHITE_PREAPARC_FIRST_DIVERGENCE_20260927.md)
tracks the first visible force difference before accepted step 6 and
explains why current compiler flag trials do not fix it.

The opt-in `--native-white-preaparc` runner now invokes this wrapper after
the CPU MNI/auxiliary/finalsurfs stages and exact topology repair, then
smooths its output for three CPU passes. The default runner path does not.
The final `white` remains a copy of that smoothwm surface until cortical
labels, annotations and the final white optimizer are integrated.

A separate [LH connected candidate-prefix replay](../../validation/recon_all/python_gpu_port/white_connected_prefix_20260927/README.md)
uses FNIT-generated MNI152 LTA, MCA/dura, venous-sinus and finalsurfs
outputs, with no official auxiliary label borrowed. It reuses the same
mixed-input topology mesh and therefore does not close that earlier MRI
boundary. Its placed surface
retains 50 vertices above 0.1 mm, and its three-pass smoothwm has 18.
The two trials have distinct upstream provenance.
