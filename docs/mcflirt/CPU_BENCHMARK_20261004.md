# MCFLIRT CPU 官方 benchmark（2026-10-04）

## 当前结果

最新生产 CPU v5 仅将 MCFLIRT 成本行内 origin、coordinate 和六项 accumulator 改为显式 float32 标量，保持逐步舍入、坐标增量与 row/plane 汇总顺序。CUDA、最终重采样与 BBR 模块保持 v4。CPU 行内核 SHA-256 为 `7c29f67f62ffb168f0b38d85e158db37966d75c81e516c2167fa987645221314`。

完整公开 180 帧、真实 490 帧、三阶段每阶段一次轮回、最终样条及正常输出均保留。17,456 次真实 CPU 成本行统计/矩统计原始字节、六项 CPU 默认/10 组完整输出、标准文件和 31 项功能组合门槛通过；最终额外完整 CUDA 180 帧与已接受 v4 精确相同，CPU 成本模块未导入。v5 focused 实测 66 项通过、12 项 CUDA 跳过，详见[默认 v5 聚合](../../validation/fmri_cpu_20261004/task01_motion_bbr/defaults_v5.public.json)。180 帧 CPU8 热 API 为 36.542 s，此前官方完整进程为 35.233 s，速度目标仍有差距。共享 CPU 调度等待和共享 GPU 负载直接记录，下文保留原始时钟，不宣布稳定加速比。

函数介绍、完整参数和 Python/CLI 示例见[使用说明](README.md)。API 的 `resample` 默认关闭；提供 `output` 会生成完整校正影像。v4 的全帧重采样、focused、六项默认、31 项功能和 36 次完整 CUDA ABBA 保留原版本，见[全帧 helper](../../validation/fmri_cpu_20261004/task01_motion_bbr/sampling_full_gate.public.json)、[v4 检查](../../validation/fmri_cpu_20261004/task01_motion_bbr/focused_suite_v4.public.json)和后文历史表。

## 输入、原软件与计时方法

| 项目 | 180 帧 | 490 帧 |
|---|---|---|
| 完整输入 | 64×64×42×180，int16，TR 2.1 s | 88×88×64×490，uint16，TR 0.735 s |
| 外部参考 | 保存的实际中间帧，float32 | 同源 3D 参考，float32 |
| 输出 | int16 校正图、180 个 MAT、180×6 `.par` | int32 校正图、490 个 MAT、490×6 `.par`、绝对/相对 RMS 及均值 |
| 精度范围 | 全部 30,965,760 个输出值 | 全部 242,851,840 个输出值；另报既有真实脑掩膜 |

公开 180 帧来自 [OpenNeuro ds001226 v5.0.1](https://openneuro.org/datasets/ds001226/versions/5.0.1)。现场原始 `dataset_description.json` 声明 CC0，SHA-256 为 `84185f9c387ae232ddbe87e20b329bacf82b9b5dafe9bde63b64c9bc78bed6f2`。私有数据只发布聚合统计。

现场 FSL 为 6.0.7.22，MCFLIRT 包为 2111.0；安装程序和来源版本的哈希保存在 [匿名报告](../../validation/fmri_cpu_20261004/task01_motion_bbr/cpu_candidate_v2.public.json)。官方参考仅在独立 benchmark 子进程调用，FNIT 运行使用自己的计算实现。

```bash
# 原完整程序；180帧和490帧均不截取时间或空间。
mcflirt -in "$RAW_BOLD" -reffile "$REFERENCE" -out "$OUTPUT_PREFIX" \
  -mats -plots -stages 3 -spline_final
# 490帧主组另保存全部标准RMS输出。
mcflirt -in "$RAW_BOLD" -reffile "$REFERENCE" -out "$OUTPUT_PREFIX" \
  -mats -plots -rmsrel -rmsabs -stages 3 -spline_final
```

CPU 实测在共享节点 nodecw8，Python 3.11.16、PyTorch 2.5.1、NumPy 1.26.4、Nibabel 5.4.2。每个进程设置 OMP、OpenBLAS、MKL、NumExpr、Numba 和 PyTorch 的 1/8 线程预算。1 线程亲和性为 CPU 8，8 线程为 8、12、16、20、24、28、32、40；同一任务锁覆盖输入/源码核验和 API。原软件实际线程数未单独采样，8 表示允许的线程与亲和性预算。

原软件计时包含 native 子进程启动、全部读取、优化、最终插值、标准文件和退出。FNIT API 包含完整影像读取与正常写盘；另记录导入、header 加载和额外未舍入证据保存。输入/源码哈希、精度分析和 `.npy` 证据保存均在 API 钟外。首次/热调用指同一进程的第一/第二次完整 API；首次不表示清空系统页缓存或 Numba 磁盘缓存。原软件与 FNIT 的进程边界不同，下面不宣布正式端到端达标。

| MCFLIRT 180 | 0.211 | 0.283 | 1.351 |
| MCFLIRT 490 | 1.154 | 1.292 | 2.397 |
| BBR | 0.810 | 1.103 | 1.655 |

显存采用十进制 GB。allocator 是每次完整 API 的精确峰值；NVIDIA owned 进程树以 0.5 s 间隔采样，后者含 CUDA context，并分别保存监控 SHA。全部低于 20 GB。该 v4 回归保留其六份源码 SHA；CPU v5 只改变 CPU 行内核，最终源码的额外单例 CUDA 完整门槛见下一节。

## 最终 CPU v5 的 CUDA 完整门槛

在 v4 的 36 次完整 ABBA 之外，对最终 v5 源码另外运行一次完整 180 帧 CUDA API。全网格 30,965,760 个影像值、binary header、180 份 4×4 矩阵和 180×6 参数均与已接受 v4 精确相同，正常 NIfTI SHA 也相同。两次 CUDA 成本求值均为 17,465，CPU 成本模块在完整 CUDA 调用前后均未导入；TF32 开启，六份源码逐项绑定。详见[最终 GPU v5 报告](../../validation/fmri_cpu_20261004/task01_motion_bbr/gpu_v5.public.json)。

| 完整 CUDA 180 帧观察 | v5 | 既有 v4 参照 |
|---|---:|---:|
| API＋正常保存（s） | 105.506 | 101.018 |
| 成本求值次数 | 17,465 | 17,465 |
| PyTorch allocation max（GB） | 0.211 | 0.211 |
| PyTorch reservation max（GB） | 0.260 | 0.260 |

v5 owned 进程树峰值 1.327 GB，采样 185 次、目标间隔 0.5 s、最大实际间隔 0.656 s，低于 20 GB cap。整体 H100 利用率的 21 个观测均为 100%，设备占用约 29.868–31.200 GB。该单例用于最终源码数值和作用域回归，时钟与历史参照分别保留，不新增稳定速度结论。

首次分析脚本把 CPU 的 17,456 次误当成 CUDA 参照，导致计数门槛失败，科学输出已精确相同。独立 v2 分析绑定已接受 CUDA 的 36-call 聚合、实际 v4 参照和输出 SHA，改用双方真实的 17,465 次，全部门槛通过。原失败文件和脚本 SHA 保留；仅重做分析，没有增加 API 调用或修改科学源码。

## CPU 标量尾段融合诊断（2026-10-06，未采用）

保留 v5 的行统计与两次原有 cumsum，只尝试融合后续 float32 标量成本。真实 180 帧调用在成本索引 588（第 589 次求值）停止：原成本为 0.0034199953079223633，候选为 0.003420114517211914，绝对差 1.1920928955078125×10⁻⁷，相当于返回成本的 512 个 float32 ULP。此前 588 对检查相同；整次 API 未完成，没有可验收的性能或 GPU 结果，因此保留生产 v5。

实际 PyTorch 2.5.1/MKL 构建和候选 native LLVM 已核查：两边均保留 float32 直接除法；平方根分别经 MKL VML 与 `sqrtf`。失败点未保存中间矩，尚不能据此确定首个不同算子。[匿名诊断报告](../../validation/fmri_cpu_20261004/task01_motion_bbr/scalar_tail_rejected.public.json)保留真实构建、返回成本和失败门槛；未放宽精度阈值。
